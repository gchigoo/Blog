# 博客后台访客分析页优化设计

**日期：** 2026-07-30
**状态：** 已确认
**范围：** `/admin/analytics` 页面、管理员 analytics API、访问采集与统计查询

## 1. 背景

当前访客分析页按“说明 → 时间范围 → 概览 → GeoLite2 状态 → 页面排行 → 七组维度卡片 → 十项筛选 → 逐次访问明细”的顺序展示。逐次访问明细位于页面靠后位置，桌面端需要穿过大量次要信息，手机端滚动距离更长。现有分页是整页导航，点击“下一页”后浏览器回到页面顶部，管理员必须再次滚动到列表。

管理员日常最关心以下信息：

1. 先看整体情况，包括今日活跃访客、所选范围内独立 IP、真人访问量和爬虫访问量。
2. 随后查看每次访问的完整 IP、具体文章、设备和访问时间。
3. 翻页和筛选时停留在访问列表，不重新回到页面顶部。
4. 已知爬虫需要保留记录和清晰标记，但不能混入真人指标。

## 2. 目标

- 将关键总览和最近访问明细提升到页面最前部。
- 明确定义并分别展示真人访问与爬虫访问。
- 在逐次访问列表中以文章标题为主、原始路径为辅。
- 桌面端提供易扫描的紧凑表格，手机端提供不横向溢出的访问卡片。
- 使用管理员 JSON API 实现列表局部筛选和无刷新翻页。
- 保留现有高级分析、GeoLite2 状态、详情查看、安全边界和无 JavaScript 降级能力。

## 3. 非目标

- 不新增第三方统计服务或外部数据上报。
- 不建立跨天或跨设备的持久用户身份。
- 不把独立 IP 等同于独立自然人。
- 不实现无限滚动、实时 WebSocket 推送或自动轮询。
- 不新增地图、复杂图表或访问路径漏斗。
- 不对历史上已被采集入口排除的爬虫访问进行推测或补录。
- 不调整访问明细的默认保留期和现有隐私边界。

## 4. 已确认的产品决策

### 4.1 页面布局采用“总览后立即进入明细”

页面顺序调整为：

1. 紧凑页头与时间范围。
2. 四项关键总览。
3. 最近访问明细、常用搜索、高级筛选和分页。
4. 默认收起的更多分析。
5. GeoLite2 与采集系统状态。

长篇采集说明不再占据页首主体空间，移入可展开的帮助说明。GeoLite2 正常状态位于页面底部；只有数据过期或更新异常时，页首显示简短告警并链接到系统状态区域。

### 4.2 统计口径

| 指标 | 口径 | 是否包含爬虫 |
|---|---|---|
| 今日活跃访客 | 北京时间当天内，按匿名日访客标识去重 | 否 |
| 独立 IP | 当前选择的近 1/7/30 天滚动范围内，原始真人 IP 去重 | 否 |
| 真人访问量 | 所选范围内成功返回公开 HTML 的真人请求次数 | 否 |
| 爬虫访问量 | 所选范围内被服务器识别为爬虫的成功公开 HTML 请求次数 | 仅此指标包含 |

“今日”使用 `Asia/Shanghai` 的自然日边界。所选范围继续使用当前“近 N 天”的滚动时间窗口。独立 IP 依赖详细访问采集；详细采集关闭时，页面显示“未启用访问明细”，不能以 `0` 冒充真实结果。

### 4.3 爬虫处理

- 常见爬虫不再在采集入口被整体丢弃。
- 爬虫逐次记录和聚合统计单独保存。
- 爬虫不进入今日活跃访客、真人独立 IP、真人访问量、真人热门文章或真人设备分布。
- 列表使用暖色“爬虫”标签，并优先显示可读名称，例如 `Googlebot`、`Bingbot`、`Applebot`；只能确定为爬虫但无法确定品牌时显示“其他爬虫”。
- 爬虫通常不会执行浏览器端上下文脚本。服务器仍生成内部事件 ID 并保存服务端明细，但不向爬虫页面注入 client-context token，也不把缺少浏览器上下文视为采集错误。

### 4.4 文章展示

文章访问在列表中显示：

- 第一行：文章标题。
- 第二行：可读访问路径，例如 `/article/node-deployment`。

标题在查询时按路径中的 slug 批量关联当前 `articles` 表，避免逐行查询。文章改名后显示当前标题；文章已删除或无法匹配时显示“文章（已删除或未知）”，仍保留原始可读路径。非文章页面使用固定名称，例如“首页”“关于”“归档”“标签页”；无法识别的公开路径以可读路径作为主名称。

## 5. 页面信息架构

### 5.1 紧凑页头

页头包含：

- 标题“访客分析”。
- 一句简短说明。
- 近 1 天、近 7 天、近 30 天切换。
- GeoLite2 或采集异常告警；正常时不显示运维信息。

时间范围切换仍是可复制、可刷新和可直接访问的 URL 参数。

### 5.2 关键总览卡片

四张卡片按以下顺序显示：

1. 今日活跃访客。
2. 所选范围独立 IP。
3. 所选范围真人访问量。
4. 所选范围爬虫访问量。

前三张使用一致的真人数据视觉语言；爬虫卡片使用克制的暖色边框或底色。卡片文案必须明确时间口径，避免把“今日活跃”和“近 7 天独立 IP”误认为同一范围。

### 5.3 最近访问工作区

总览后立即显示最近访问。工作区由以下部分组成：

- 结果标题和当前结果摘要。
- 常用搜索。
- 真人/爬虫快捷筛选。
- 可展开的高级筛选。
- 访问记录列表。
- 局部分页状态与上一页/下一页操作。
- 局部错误和重试操作。

#### 常用搜索

单一搜索框支持搜索：

- 完整或部分 IP。
- 文章标题。
- 访问路径。

服务端必须限制长度、规范化输入并转义 SQL `LIKE` 通配符。现有完整 IP 精确筛选保留在高级筛选中。

#### 快捷筛选

常驻选项为：

- 全部访问。
- 仅真人。
- 仅爬虫。

默认显示全部访问，让爬虫记录在时间流中可见。选择“仅真人”或“仅爬虫”只改变逐次列表，不改变页面顶端四项总览的既定口径。

#### 高级筛选

以下条件默认收起：

- 完整 IP。
- 国家、一级行政区、城市。
- 浏览器、操作系统、设备类别。
- 路径前缀。
- 来源域。

已应用高级筛选时，折叠区标题显示筛选数量，并在工作区顶部展示可单独移除的筛选摘要，避免用户忘记当前条件。

### 5.4 桌面列表

桌面端使用五列紧凑表格：

| 列 | 主信息 | 辅助信息 |
|---|---|---|
| 访问时间 | `HH:mm:ss` | 今天/昨天或完整日期 |
| 访问页面 | 文章标题或页面名称 | 可读路径 |
| IP / 地区 | 完整 IP | 国家、一级行政区、城市中的可用部分 |
| 设备 | 设备类别或爬虫标签 | 浏览器与操作系统，或爬虫名称 |
| 操作 | 查看详情 | 无 |

“来源”不再占用主表列宽，保留在详情面板中。字段缺失时显示“未知”，不拼接多余分隔符。

### 5.5 手机列表

小于移动断点时，每条访问变为卡片，而不是压缩桌面表格。卡片顺序为：

1. 文章标题或页面名称与访问时间。
2. 可读路径。
3. IP 与地区。
4. 设备、浏览器和系统，或爬虫名称。
5. 查看详情操作。

卡片必须允许 IPv6、长 slug 和长设备名称换行，不产生页面级横向滚动。

### 5.6 更多分析与系统状态

现有页面排行和七组维度分析移到访问列表之后，放入原生可访问的折叠区域。默认收起，展开后保留现有维度快捷筛选能力。维度统计默认只反映真人访问。

GeoLite2 状态位于页面末尾另一个系统状态区域。状态异常时页首告警与该区域通过锚点关联。

## 6. 数据与服务端设计

### 6.1 统一客户端分类器

新增独立的 analytics 客户端分类模块，输入原始 User-Agent，输出不可变结果：

```js
{
  trafficKind: 'human' | 'bot',
  botName: null | 'Googlebot' | 'Bingbot' | 'Applebot' | 'Other bot'
}
```

识别规则集中维护并按具体品牌优先、通用模式兜底的顺序匹配。分类器负责替代当前 `middleware.js` 中只用于排除的 `BOT_PATTERN`，避免采集逻辑、查询逻辑和 UI 各自维护不同规则。

规则只把明确命中的 User-Agent 判为爬虫。空 User-Agent 或难以识别的客户端保持真人/未知客户端路径，不因设备解析失败自动判为爬虫，以减少误报。

### 6.2 数据库字段

在 `access_metrics` 增加：

- `traffic_kind TEXT NOT NULL DEFAULT 'human' CHECK (traffic_kind IN ('human', 'bot'))`

在 `access_event_details` 增加：

- `traffic_kind TEXT NOT NULL DEFAULT 'human' CHECK (traffic_kind IN ('human', 'bot'))`
- `bot_name TEXT`

新增支持时间范围和列表筛选的索引，至少覆盖：

- `access_metrics(traffic_kind, bucket_utc)`。
- `access_event_details(traffic_kind, observed_at_utc DESC, metric_id DESC)`。

现有记录全部回填为 `human`，因为旧采集逻辑已在写入前排除已知爬虫。不能恢复旧爬虫数据。

`traffic_kind` 同时存于聚合行和明细行，使详细采集关闭时仍能统计真人与爬虫访问量；明细开启时则能查询独立 IP 和逐次爬虫记录。两个字段必须在同一数据库事务中写入并保持一致。

### 6.3 采集流程

采集流程调整为：

1. 继续检查方法、公开路径、文件扩展名、内部 IP、响应状态和 HTML Content-Type。
2. 捕获 User-Agent 并调用统一分类器。
3. 为真人访问生成按北京时间日期分桶的匿名日访客 HMAC。
4. 为爬虫访问写入独立 `traffic_kind`；其 HMAC 可以写入稳定占位值，但任何真人查询都必须显式过滤 `traffic_kind = 'human'`。
5. 详细采集开启时，在同一事务中写入聚合行和访问明细。
6. 真人访问继续获得浏览器上下文 token；爬虫访问不获得该 token。

匿名日访客 HMAC 的日期组成从 UTC 日期改为 `Asia/Shanghai` 日期，以匹配“今日活跃访客”的产品口径。密钥和原始 IP 处理方式保持不变。部署切换当天，旧记录的 UTC 日标识无法无损换算为北京时间日标识；今日活跃访客可能在最多一个自然日内出现轻微过度去重或重复计数，之后自动恢复稳定。该限制需要写入发布说明，不对旧 HMAC 做不可验证的重算。

### 6.4 总览查询

`getOverview` 保留旧字段以降低兼容风险，并新增明确字段：

```js
{
  todayActiveVisitors,
  uniqueHumanIps,
  humanPageViews,
  botPageViews,
  detailsAvailable
}
```

查询规则：

- `todayActiveVisitors`：北京时间今日起点至当前时刻，`access_metrics` 中真人 `visitor_day_hmac` 去重。
- `uniqueHumanIps`：所选滚动范围内，`access_event_details` 中真人 `ip_address` 去重。
- `humanPageViews`：所选范围内 `access_metrics` 真人行数。
- `botPageViews`：所选范围内 `access_metrics` 爬虫行数。
- 现有 `byPage`、`byDevice` 和明细维度默认增加真人过滤。

总览缓存键继续包含范围和时间片；任何真人或爬虫记录写入都使缓存失效。100k 事件性能测试必须覆盖新增过滤和独立 IP 查询。

### 6.5 事件列表查询

事件列表响应新增：

```js
{
  trafficKind,
  botName,
  page: {
    kind: 'article' | 'home' | 'about' | 'archive' | 'tag' | 'other',
    title,
    displayPath
  }
}
```

查询参数新增：

- `traffic=all|human|bot`，默认 `all`。
- `search=<text>`，用于 IP、文章标题和路径搜索。

现有过滤参数和稳定游标继续使用。文章标题映射必须批量完成，不能对每条事件执行一次文章查询。游标排序继续以 `observed_at_utc DESC, metric_id DESC` 为唯一稳定顺序。

当查询包含文章标题搜索时，服务端可使用受约束的 `LEFT JOIN articles` 或先匹配 slug 集合后构建参数化查询；无论采用哪种实现，都必须参数化、转义通配符并通过 `EXPLAIN QUERY PLAN` 和性能测试验证。

### 6.6 详情 API

单条详情响应也包含 `trafficKind`、`botName` 和页面标题信息。爬虫详情保留原始 User-Agent 和服务端解析结果。浏览器上下文字段为空时，UI 显示“爬虫未提供浏览器上下文”，而不是错误提示。

## 7. 前端交互设计

### 7.1 渐进增强

初次请求仍由 EJS 输出完整总览、筛选表单、首屏记录和可用的普通分页链接，保证：

- 页面可直接刷新和分享筛选 URL。
- JavaScript 加载失败时仍可筛选和翻页。
- 服务端渲染内容继续经过 EJS 转义。

JavaScript 启用后拦截访问工作区内的筛选和分页操作，改用 `/api/admin/analytics/events` 获取 JSON。

### 7.2 无刷新分页

客户端维护：

- 当前筛选参数。
- 当前游标。
- 已访问页面的游标栈，用于“上一页”。
- API 返回的下一页游标。

交互顺序：

1. 用户提交筛选或点击上一页/下一页。
2. 当前列表保持可见，工作区显示 `aria-busy="true"` 并禁用重复操作。
3. 请求管理员事件 API。
4. 成功后仅替换结果摘要、列表和分页控件。
5. 使用 History API 更新地址栏查询参数，不触发页面跳转，也不调用滚动定位。
6. 将焦点移到更新后的结果摘要，而不是页面顶部；屏幕阅读器通过礼貌状态区域获知结果变化。

浏览器前进/后退时根据 URL 恢复对应列表。筛选改变后清空游标栈并从第一页开始。

### 7.3 错误处理

- 请求失败时保留旧列表、旧游标和滚动位置。
- 列表上方显示可聚焦错误信息与“重试”按钮。
- 不使用空表或全页错误替代当前数据。
- 竞态请求使用 `AbortController` 取消；只允许最后一次请求更新 UI。
- API 返回无效筛选时显示具体的筛选错误，不自动清空用户输入。

### 7.4 详情面板

详情面板继续使用文本节点写入数据，不拼接不可信 HTML。面板增加：

- 页面标题。
- 真人/爬虫类型。
- 爬虫名称。
- 来源。

桌面端可保持页面内详情面板；手机端同样必须在当前文档流中展开，不引入难以操作的宽模态框。

## 8. 视觉与可访问性

设计保持项目现有极简后台风格，不引入新的 UI 框架。重点通过间距、字号、边框和信息层级提升扫描效率。

- 总览卡片在宽屏为四列，在窄屏逐步降为两列和单列。
- 真人标签使用冷色或中性色；爬虫标签使用暖色，同时保留文字，不能只靠颜色区分。
- 表头、筛选控件和分页按钮具备可见焦点样式。
- 折叠区使用原生 `<details>/<summary>` 或等价的可访问实现。
- 加载、成功和错误状态通过 `role="status"` 或 `role="alert"` 宣告。
- IPv6、Unicode 路径、长文章标题和长 User-Agent 均允许安全换行。
- 手机端不得出现页面级横向滚动。

## 9. 安全与隐私

- 管理页面和 API 继续要求现有管理员认证并设置 `Cache-Control: no-store`。
- 原始 IP 只在管理员页面和认证 API 中返回。
- 搜索和筛选继续严格限制类型与长度，所有 SQL 使用参数绑定。
- 页面标题、路径、地区、User-Agent 和来源等不可信值继续使用 EJS 转义或 `textContent` 写入。
- 爬虫分类不能读取或保存新的敏感字段。
- 现有 Cookie、Authorization、OAuth 参数和凭据参数清洗规则保持不变。
- 访问明细清理继续覆盖真人和爬虫数据，并遵守同一保留期。

## 10. 兼容与迁移

- `initializeAnalytics` 以可重复执行方式添加新列和索引。
- 旧 `access_metrics` 与 `access_event_details` 行回填为 `human`。
- 旧 API 字段暂时保留；新页面优先使用语义明确的新字段。
- 详细采集关闭时，真人/爬虫页面访问量仍可由聚合表提供；独立 IP 与逐次明细显示明确不可用状态。
- 现有游标格式可以继续使用，因为排序键不变；新增筛选只改变游标对应的结果集合。
- 更新部署说明，明确启用本页面完整能力仍需 `ANALYTICS_DETAILS_ENABLED=true`。

## 11. 测试计划

### 11.1 单元与数据库测试

- 具体爬虫品牌、通用 bot 模式、普通浏览器、空 User-Agent 和伪装字符串的分类结果。
- 新字段和索引可在新库与旧库上重复初始化。
- 真人与爬虫在同一事务中写入一致分类。
- 旧记录正确回填为真人。
- 北京时间日期边界前后的匿名日 HMAC 和今日活跃统计。
- 爬虫不进入真人日活、独立 IP、真人访问量和真人维度。
- 爬虫访问量与爬虫逐次记录正确保留。
- 独立 IP 在所选范围内正确去重。
- 保留期清理同时删除真人和爬虫记录。

### 11.2 查询与 API 测试

- `traffic=all|human|bot` 和非法值处理。
- IP、路径和文章标题统一搜索。
- `%`、`_`、Unicode 和超长搜索输入的安全处理。

## 12. 验收标准

1. 打开 `/admin/analytics` 后，无需经过维度统计即可看到四项总览和最近访问。
2. 今日活跃访客按北京时间当天统计，且不包含爬虫。
3. 独立 IP 按所选范围对真人 IP 去重；明细关闭时显示不可用而非零。
4. 爬虫访问会被保存、命名和标记，但不进入任何真人指标。
5. 文章访问优先显示文章标题，并保留路径作为辅助信息。
6. 桌面端能同时快速扫描时间、文章、IP 和设备；手机端无横向溢出。
7. 点击下一页、上一页或应用筛选时不发生整页跳转，不回到页面顶部。
8. 局部请求失败时现有列表和滚动位置保持不变，并可重试。
9. 无 JavaScript 时仍能完成筛选、查看列表和分页。
10. 现有认证、转义、保留期、GeoIP 和性能测试约束继续通过。
